# Implementation Plan: Practice Arena (ساحة التدريب)

**Branch**: `025-practice-arena` | **Date**: 2026-02-23 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/025-practice-arena/spec.md`

## Summary

Student-initiated practice mode where students select specific content (track/unit/topic) and answer multiple-choice questions without affecting FSRS state, streaks, leaderboards, or XP. Built on the Review Item table from phase 024, with a new raw SQL Practice Log table for per-student history, ephemeral Redis sessions, and 4 FastAPI endpoints. Gap-filling from phase 024 includes: Practice Log cascade deletion, `is_reviewable` filtering, MINDMAP recursive extraction, and content_hash debounce.

## Technical Context

**Language/Version**: Python 3.11+ (Frappe v15 bench environment)
**Primary Dependencies**: FastAPI, Pydantic v2, redis.asyncio, structlog, Frappe Framework (ORM for Review Items, raw SQL for Practice Log)
**Storage**: MariaDB via Frappe ORM (Review Items) + raw SQL (Practice Log, ~500M rows), Redis at `redis://127.0.0.1:13000` (practice sessions, hierarchy cache)
**Testing**: pytest 8.4.2, pytest-asyncio, httpx (FastAPI), FrappeTestCase (Frappe-side), real Redis (no mocking)
**Target Platform**: Linux server (FastAPI on port 8002, Frappe bench)
**Project Type**: Dual architecture (Frappe admin + FastAPI sidecar)
**Performance Goals**: <100ms question selection (SC-003), <2s P95 end-to-end (SC-001), <30s sync for 100 lessons (SC-002)
**Constraints**: 100K concurrent users, no impact on daily review system (FR-015), one session per player
**Scale/Scope**: ~200K Review Items, ~500M Practice Log rows, 4 new endpoints, 1 new raw SQL table, 43 tasks across 8 phases

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

### Pre-Design Gate

| Principle | Status | Notes |
|-----------|--------|-------|
| I. Self-Healing Cache | **COMPLIANT** | Practice Sessions are Redis-only but intentionally ephemeral (not source-of-truth). Practice Log is MariaDB (source of truth). Review Items use existing Frappe DocType with hydration. No new self-healing pattern needed. |
| II. Sub-20ms Game API | **DEVIATION JUSTIFIED** | Question selection target is <100ms (not <20ms) due to SQL JOIN complexity (Review Item × Practice Log). This is acceptable: practice is a deliberate user action, not real-time game flow. Hierarchy endpoint uses cached data (<5ms). |
| III. Content Hierarchy Integrity | **COMPLIANT** | Read-only consumer of existing hierarchy. No modifications to bitmap, version, or bit_index structures. |
| IV. Double-Gate Access Control | **COMPLIANT** | Reuses existing `AccessService.check_access_with_plan()`. Access checked at session start only (FR-008/FR-009). Free content bypass maintained. |
| V. Cryptographic Voucher Security | **N/A** | No voucher operations. |
| VI. Financial Precision | **N/A** | No monetary calculations. No XP/rewards. |
| VII. Auditable State Machines | **COMPLIANT** | Practice sessions are ephemeral (no audit trail needed). Practice Log is append/update only (never transitions backward). |
| VIII. Test-First Coverage | **COMPLIANT** | Real Redis for FastAPI tests (Phase 7: T035-T041). Raw SQL tests for Practice Log (Phase 6: T034). FrappeTestCase for Review Item gap-fill tests (Phase 6: T031-T033). Success criteria validation (Phase 8: T042-T043). |

### Post-Design Gate

| Principle | Status | Notes |
|-----------|--------|-------|
| I. Self-Healing Cache | **COMPLIANT** | Session loss = student restarts (by design). Hierarchy cache has existing self-healing. Settings cache: Redis miss → Frappe fallback. |
| II. Sub-20ms Game API | **DEVIATION JUSTIFIED** | Question selection is a batch query (~10-20ms estimated via indexed JOIN), not a per-action hot path. Session start/submit are <10ms (Redis-only). |
| IV. Double-Gate Access Control | **COMPLIANT** | Session start validates Season (Gate 1) + content access (Gate 2) in `_get_accessible_lessons()` (T019). For inaccessible tracks, free content bypass still includes free topics/units. Subsequent batches use stored `accessible_lessons` list — no re-check per FR-009. |
