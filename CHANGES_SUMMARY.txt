================================================================================
CRITICAL FIELDS & THEIR PURPOSES
================================================================================

PLAYER PROGRESSION:
  total_xp → Cumulative experience points
  current_streak → Days of consecutive activity
  completion_percentage → Subject progress (0-100%)
  passed_lessons_bitset → Efficient lesson completion tracking

LEARNING ALGORITHMS:
  stability → FSRS memory stability (higher = stronger)
  difficulty → FSRS question difficulty (0-1)
  next_review → When to show content for review
  is_reviewable → Lesson eligibility for spaced repetition

CONTENT MANAGEMENT:
  json_version → Cache bust trigger
  json_hash → Integrity verification
  redis_key_prefix → Storage location identifier
  content_hash → Lesson version control

GAMIFICATION:
  base_xp → First completion reward
  max_hearts → Allowed attempts
  xp_per_heart → Bonus per remaining heart
  replay_xp → Recompletion reward

SYSTEM CONFIG:
  dirty_flag → Redis ↔ DB sync indicator
  signed_url_expiry_hours → CDN link validity
  batch_interval_minutes → Sync frequency
  fsrs_weights → Algorithm parameters (JSON)

================================================================================
FIELD NAMING CONVENTIONS
================================================================================

Prefixes:
  sb_* → Section Breaks (UI organization)
  total_* → Aggregated counts
  is_* → Boolean flags
  ref_* → Reference/foreign key
  bit_* → Related to bitset operations

Common Patterns:
  {entity}_title → Display name
  {entity}_id → Unique identifier
  {entity}_at → Timestamp
  column_break_* → UI layout helpers

Sections Used:
  sb_stats → Statistics section (count aggregates)
  sb_json → JSON generation fields
  sb_hierarchy → Content hierarchy relations
  sb_unlock → Achievement unlock conditions
  sb_rewards → Gamification rewards
