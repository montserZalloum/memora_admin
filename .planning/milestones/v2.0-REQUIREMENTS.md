## v2.0 Requirements

Requirements for mobile-first player authentication migration. Each maps to roadmap phases.

### Schema & DocType (7/7)

- [x] **SCHEMA-01**: Player Profile autoname changed from `field:user` to `PLAYER-.#####.` — Phase 29
- [x] **SCHEMA-02**: `mobile` field added (Data, unique, required) as primary player identifier — Phase 29
- [x] **SCHEMA-03**: `password` field added (Password fieldtype, hidden) with `flags.ignore_save_passwords` bypass — Phase 29
- [x] **SCHEMA-04**: Phone normalization in `validate()` — strips non-digits, validates 9-15 digit length — Phase 29
- [x] **SCHEMA-05**: Password hashing via `update_password()` in `after_insert`/`on_update` (PBKDF2-SHA256, not Fernet) — Phase 29
- [x] **SCHEMA-06**: `user` field kept temporarily (nullable, not required) for backward compatibility — Phase 29, removed in Phase 32

### Player Authentication (5/5)

- [x] **AUTH-01**: Player can log in with phone number + password via `POST /auth/player/login` — Phase 31
- [x] **AUTH-02**: Login calls Frappe whitelisted API (`verify_player_password`) — single HTTP call, no Frappe session — Phase 31
- [x] **AUTH-03**: Login returns enriched response (tokens + display_name, avatar, gender, XP) — Phase 31
- [x] **AUTH-04**: Admin can log in with email + password via `POST /auth/admin/login` (existing Frappe User flow) — Phase 31
- [x] **AUTH-05**: Token refresh works for both player and admin tokens via `POST /auth/refresh` — Phase 31

### Registration (6/6)

- [x] **REG-01**: Player can self-register via `POST /auth/player/register` (sends OTP) — Phase 31
- [x] **REG-02**: Player verifies OTP via `POST /auth/player/register/verify` (creates account) — Phase 31
- [x] **REG-03**: OTP stored in Redis with 5-minute TTL, static "1111" stub with pluggable provider interface — Phase 31
- [x] **REG-04**: Phone reservation during OTP window prevents duplicate registration attempts — Phase 31
- [x] **REG-05**: OTP resend with 60-second cooldown via `POST /auth/player/register/resend` — Phase 31
- [x] **REG-06**: Player Profile, wallet, and initial Redis state created on successful registration — Phase 31

### Password Reset (6/6)

- [x] **RESET-01**: Player requests OTP via `POST /auth/player/password-reset/request` — Phase 31
- [x] **RESET-02**: Player verifies OTP and receives temp token via `POST /auth/player/password-reset/verify` — Phase 31
- [x] **RESET-03**: Player sets new password with temp token via `POST /auth/player/password-reset/confirm` — Phase 31
- [x] **RESET-04**: Temp token is cryptographically random (secrets.token_urlsafe(32)), bound to phone, 10-min TTL, single-use — Phase 31
- [x] **RESET-05**: All existing sessions invalidated on password change (OWASP requirement) — Phase 31
- [x] **RESET-06**: Admin can reset player password from Frappe Desk (triggers session invalidation) — Phase 30

### Security (5/5)

- [x] **SEC-01**: OTP send rate limiting — 3 per phone per 10 min, 10 per IP per 10 min — Phase 31
- [x] **SEC-02**: OTP verification attempt limiting — max 3 incorrect attempts, then invalidate OTP — Phase 31
- [x] **SEC-03**: Password policy — minimum 8 characters enforced in validate() and FastAPI — Phase 29
- [x] **SEC-04**: Pluggable OTP provider interface (OTPProvider protocol) with StaticOTPProvider default — Phase 31
- [x] **SEC-05**: 60-second cooldown between OTP resends to same number — Phase 31

### Code Migration (7/7)

- [x] **MIGR-01**: JWT `sub` = Player Profile docname (PLAYER-00001), `mobile` claim for phone number — Phase 31
- [x] **MIGR-02**: `create_access_token()` updated — `email` optional, `mobile` added — Phase 31
- [x] **MIGR-03**: Event handlers updated — `doc.user` replaced with `doc.name` in access_sync, device_sync, plan_change_sync, profile_sync — Phase 32
- [x] **MIGR-04**: Frappe APIs updated — purchase.py, profile.py, subscriptions.py, devices.py remove `{"user": player_id}` lookups — Phase 32
- [x] **MIGR-05**: Frappe whitelisted auth API created (`memora_admin/api/auth.py`) with verify_player_password, register_player, set_player_password — Phase 30
- [x] **MIGR-06**: Fix pre-existing bug: plan_change_sync.py and profile_sync.py use wrong Redis client (frappe.cache() instead of get_fastapi_redis()) — Phase 32
- [x] **MIGR-07**: Old single `/auth/login` endpoint removed, replaced by separate player/admin endpoints — Phase 31
