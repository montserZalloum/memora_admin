# Milestone v2.0: Mobile-First Player Authentication

**Status:** SHIPPED 2026-02-12
**Phases:** 29-32
**Total Plans:** 9

## Overview

Replace Frappe User-based email authentication for players with phone+password model on Player Profile DocType. Players authenticate via phone number + password stored directly in Memora Player Profile. Admins keep Frappe User email auth.

## Phases

### Phase 29: DocType Schema Foundation

**Goal**: Player Profile DocType supports phone+password identity with proper hashing, normalization, and backward compatibility
**Depends on**: Phase 28 (v1.9 complete)
**Plans**: 1 plan

Plans:
- [x] 29-01: JSON schema + Python class hooks for phone+password identity

**Details:**
- Changed autoname from `field:user` to `PLAYER-.#####.`
- Added `mobile` field (Data, unique, in_list_view)
- Added `password` field (Password, hidden) with `flags.ignore_save_passwords` bypass
- Phone normalization (digits-only, 9-15 length) in validate()
- PBKDF2-SHA256 hashing via `update_password()` in after_insert/on_update
- Password policy: minimum 8 characters
- `user` field kept temporarily (nullable) for backward compatibility

### Phase 30: Frappe Auth API Bridge

**Goal**: FastAPI can verify player passwords and manage player accounts through Frappe without creating Frappe sessions
**Depends on**: Phase 29
**Plans**: 1 plan

Plans:
- [x] 30-01: Frappe auth API (3 whitelisted functions) + Desk Reset Password button

**Details:**
- `verify_player_password(mobile, password)` — phone-to-docname resolution, PBKDF2 check via __Auth, returns profile + XP
- `register_player(mobile, password, plan, grade, ...)` — creates Player Profile with wallet, returns profile dict
- `set_player_password(player_name, new_password)` — hash update + session invalidation
- Desk "Reset Password" button on Player Profile form with dialog UI
- Anti-enumeration: generic error for both not-found and wrong-password
- Non-fatal Redis operations (wallet init, session invalidation)

### Phase 31: FastAPI Auth Endpoints + OTP System

**Goal**: Players can register, log in, and reset passwords via the mobile app using phone number + password, with OTP verification for registration and password reset
**Depends on**: Phase 30
**Plans**: 4 plans

Plans:
- [x] 31-01: Core infrastructure — JWT updates, Pydantic models, config, OTP service
- [x] 31-02: Player login, admin login, and token refresh endpoints
- [x] 31-03: Registration flow (2-step OTP) + registration options endpoint
- [x] 31-04: Password reset flow (3-step OTP)

**Details:**
- 10 FastAPI auth endpoints total
- OTPService (409 lines): Redis-backed storage, pluggable OTPProvider protocol, StaticOTPProvider dev stub
- Rate limiting: 3/phone/10min, 10/IP/10min via atomic Lua INCR+EXPIRE
- OTP verification: max 3 incorrect attempts, then invalidation
- 60-second cooldown between resends
- Player login via FrappeClient.call(verify_player_password) — single HTTP call, no Frappe session
- Admin login retains FrappeAuthService (Frappe User auth unchanged)
- Registration: upfront phone check, 2-step OTP verify, auto-login after creation
- Password reset: 3-step OWASP-compliant flow with anti-enumeration (consistent timing)
- Registration options: grades, plans, seasons, avatars, genders with Redis caching

### Phase 32: Event Handler & API Migration

**Goal**: All event handlers and Frappe APIs work with the new Player Profile identity model (docname-based instead of user-based)
**Depends on**: Phase 31
**Plans**: 3 plans

Plans:
- [x] 32-01: Event handlers (access_sync, device_sync, plan_change_sync, profile_sync) + schema user field removal
- [x] 32-02: Frappe APIs (purchase, profile, subscriptions, devices, reviews) docname migration
- [x] 32-03: Scheduled tasks (profile_cache, fsrs_processor) identity + Redis fix

**Details:**
- 4 event handlers migrated: doc.user → doc.name/doc.player
- profile_sync.py and plan_change_sync.py: frappe.cache() → get_fastapi_redis() with two-pronged invalidation
- access_sync.py simplified: doc.player used directly (no frappe.get_doc lookup)
- 5 Frappe APIs migrated: eliminated all `{"user": player_id}` lookups
- Subscription fallback blocks removed (30+ lines dead code)
- reviews.py pp.user → pp.name (discovered during verification grep)
- profile_cache.py: name field queries + get_fastapi_redis()
- fsrs_processor.py: pp.name SQL JOIN for player resolution
- Player Profile JSON schema: user field removed (clean break)

## Milestone Summary

**Key Decisions:**
- Phone+password auth for players (Frappe User overhead unnecessary for mobile-first audience)
- PLAYER-.#####. autoname (decouples identity from phone number; avoids rename_doc)
- Separate player/admin login endpoints (clean separation, no detection heuristics)
- Static OTP "1111" stub (ship auth flow now, swap real SMS/WhatsApp provider later)
- 3-step password reset (most secure OTP flow per OWASP)
- Anti-enumeration: consistent timing regardless of phone existence
- FrappeClient.call for player login (single HTTP call vs 4-call FrappeAuthService flow)
- session_timeout_days from Memora Settings drives player refresh token TTL
- OTPProvider protocol for pluggable SMS delivery

**Issues Resolved:**
- profile_sync.py and plan_change_sync.py using wrong Redis client (frappe.cache() instead of get_fastapi_redis()) — fixed in Phase 32
- reviews.py pp.user SQL bug discovered during migration verification grep — fixed in Phase 32
- All 4 doc.user anti-patterns in event handlers (flagged in Phase 29 audit) — resolved in Phase 32

**Issues Deferred:**
- Real SMS/WhatsApp OTP delivery — pluggable interface ready, static "1111" for now
- Phone number change flow — admin-only via Frappe Desk
- Existing player data migration — fresh start; handle manually if needed

**Technical Debt Incurred:**
- None. All Phase 29 anti-patterns resolved in Phase 32 as planned.
