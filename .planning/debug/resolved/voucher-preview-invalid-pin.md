## Resolution

root_cause: VOUCHER_HMAC_SECRET was missing from FastAPI .env file. The Settings config defaulted to empty string "". Cards were generated by Frappe using voucher_hmac_secret="memora" from site_config.json. HMAC-SHA256("", pin) produces a completely different hash than HMAC-SHA256("memora", pin), so the SQL `WHERE pin_hmac = %s` lookup returned zero rows, producing INVALID_PIN for every PIN.

fix: |
  1. Added VOUCHER_HMAC_SECRET=memora to .env (matching Frappe's site_config.json)
  2. Added ValueError guard in VoucherService.__init__() to fail loudly if hmac_secret is empty
  3. Restarted FastAPI to pick up both changes

verification: |
  - Confirmed Settings().voucher_hmac_secret now loads "memora" (length 6)
  - Confirmed HMAC("memora", "K9FVNYBMGPD5") = 066cfab9541d4a14... matches VCH-000002 pin_hmac in DB
  - Confirmed HMAC("", "K9FVNYBMGPD5") = 94c81489... does NOT match (proving the root cause)
  - FastAPI health check passes after restart

files_changed:
  - .env (added VOUCHER_HMAC_SECRET=memora)
  - fastapi_app/services/voucher.py (added empty-secret guard in __init__)
