2. **Extend `fastapi_app/models/profile.py`** -- Keep existing `PlayerProfile` model intact. Add these NEW models below it:

   ```python
   class HeroResponse(BaseModel):
       """Profile hero section."""
       display_name: str
       avatar: str
       level: int
       level_title: str
       current_xp: int          # Total XP
       xp_in_level: int         # XP earned within current level
       xp_for_next_level: int   # XP remaining to next level (0 if max)
       xp_level_start: int      # XP threshold for current level
       xp_level_end: int        # XP threshold for next level (0 if max)

   class StatsResponse(BaseModel):
       """Stats grid data."""
       subject: str | None = None  # None = combined across all subjects
       streak: int
       items_learned: int
       total_xp: int

   class MemoryMasteryResponse(BaseModel):
       """Memory mastery breakdown from FSRS."""
       subject: str | None = None
       mature: int
       learning: int
       new_items: int
       total: int

   class DailyXP(BaseModel):
       """Single day's XP data."""
       date: str           # YYYY-MM-DD
       day_name: str        # Mon, Tue, etc.
       xp: int

   class WeeklyActivityResponse(BaseModel):
       """Weekly activity chart data."""
       subject: str | None = None
       week_start: str      # Monday YYYY-MM-DD
       days: list[DailyXP]
       total_xp: int

   class AvatarUpdateRequest(BaseModel):
       """Request to change avatar."""
       avatar: str

   class AvatarUpdateResponse(BaseModel):
       """Response after avatar change."""
       avatar: str
       success: bool

   class AvatarOptionsResponse(BaseModel):
       """Available avatar options."""
       avatars: list[str]

   class LogoutResponse(BaseModel):
       """Response after logout."""
       success: bool
       message: str = "Logged out successfully"
   ```

Extend `memora_admin/api/profile.py` (keep existing `get_profiles_batch` function intact). Add three new whitelisted functions:

1. **`get_memory_mastery(player_id: str, subject_id: str | None = None) -> dict`**
   - Classify Memory States into mature/learning/new using SQL aggregation on `tabMemora Memory State`
   - SQL query:
     ```sql
     SELECT
       COALESCE(SUM(CASE WHEN stability >= 21.0 THEN 1 ELSE 0 END), 0) as mature,
       COALESCE(SUM(CASE WHEN stability > 0 AND stability < 21.0 THEN 1 ELSE 0 END), 0) as learning,
       COALESCE(SUM(CASE WHEN stability = 0 THEN 1 ELSE 0 END), 0) as new_items
     FROM `tabMemora Memory State`
     WHERE player = %(player)s
     {AND subject = %(subject)s -- only if subject_id provided}
     ```
   - Use `.format()` for conditional subject filter (same pattern as RESEARCH.md example)
   - Return `{"mature": int, "learning": int, "new_items": int, "total": mature+learning+new_items}`
   - Handle `subject_id` being `str | None` -- if it arrives as JSON string "null", treat as None

2. **`update_player_avatar(player_id: str, avatar: str) -> dict`**
   - Look up the player's `Memora Player Profile` by `user` field (not doctype name)
   - Use `frappe.get_value("Memora Player Profile", {"user": player_id}, "name")` to find the profile doc name
   - Validate avatar is in the allowed options by reading the DocType field definition:
     ```python
     meta = frappe.get_meta("Memora Player Profile")
     avatar_field = meta.get_field("avatar")
     valid_options = [opt.strip() for opt in (avatar_field.options or "").split("\n") if opt.strip()]
     ```
   - If avatar not in valid_options, raise `frappe.ValidationError("Invalid avatar option")`
   - Update via `frappe.db.set_value("Memora Player Profile", profile_name, "avatar", avatar)`
   - `frappe.db.commit()`
   - Return `{"avatar": avatar, "success": True}`

3. **`get_avatar_options() -> list[str]`**
   - Read valid avatar options from DocType meta (same method as above)
   - Return list of valid avatar strings
   - No player_id needed -- options are global

All three functions decorated with `@frappe.whitelist(allow_guest=False)`.
