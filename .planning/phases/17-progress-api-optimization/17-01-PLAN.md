<objective>
Create a pre-computed stats caching layer that maintains completion counts in Redis hash, updated atomically on lesson completion.

Purpose: Current progress endpoint uses O(N) operations (BITCOUNT, pipeline GETBIT) that scale poorly with subject size (50K+ lessons). This plan introduces O(1) stats reads and atomic updates.

Output: StatsService with Redis hash operations, wired into session completion flow and progress endpoint.
</objective>

  <name>Task 1: Create StatsService</name>
  <files>fastapi_app/services/stats.py</files>
  <action>
Create StatsService class following project patterns (see HierarchyService, ProfileService).

**Redis key pattern:**
```
memora:stats:{user_id}:{subject_id}:v{version}  # Hash
```

**Hash fields stored:**
- `completed`: total lessons completed
- `total`: total lessons in subject
- `{track_id}:completed`, `{track_id}:total`
- `{unit_id}:completed`, `{unit_id}:total`
- `{topic_id}:completed`, `{topic_id}:total`

**Methods to implement:**

1. `_stats_key(user_id, subject_id, version) -> str`
   - Generate Redis key for stats hash

2. `async def increment_completion_stats(user_id, subject_id, version, track_id, unit_id, topic_id) -> None`
   - Use pipeline with HINCRBY for atomic increment of all 4 counters (subject + track + unit + topic completed)
   - Refresh TTL (CACHE_TTL = 3600) on update via `pipe.expire(key, self.CACHE_TTL)`
   - Per research: O(1) per field, O(4) total

3. `async def get_stats(user_id, subject_id, version) -> dict[str, str] | None`
   - HGETALL to retrieve all stats
   - Return None if key doesn't exist (signals need for lazy init)
   - Handle bytes decoding for Redis response

4. `async def set_stats(user_id, subject_id, version, stats: dict[str, str]) -> None`
   - HSET with mapping to initialize cache from computed values
   - Set TTL via EXPIRE

5. `async def invalidate_stats(user_id, subject_id, version) -> None`
   - DELETE the stats key (for cache invalidation if needed)

**Helper function (module-level):**

6. `def compute_stats_from_hierarchy(hierarchy: SubjectHierarchy, completed_bits: set[int]) -> dict[str, str]`
   - Walk hierarchy tree, count completed/total at each level
   - Return dict suitable for HSET mapping (all values as strings)
   - Per research code example in 17-RESEARCH.md

**Class attributes:**
- `CACHE_TTL = 3600`  # 1 hour, matches HierarchyService

**Constructor:**
```python
def __init__(self, redis_client: redis.Redis, key_prefix: str = "memora:"):
    self.redis = redis_client
    self.prefix = key_prefix
```

Import redis.asyncio as redis. Follow existing service patterns for type hints.

   stats = await stats_service.get_stats(

       subject_id=subject,

           subject_id=subject,
           version=hierarchy.version,
           stats=stats,
