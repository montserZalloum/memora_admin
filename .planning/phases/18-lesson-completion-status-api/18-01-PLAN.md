<objective>
Implement GET /progress/{subject}/topics/{topic_id}/lessons endpoint for fast per-lesson completion lookups.

Purpose: Frontend topic pages need to display completion status for individual lessons (checkmarks, progress indicators). Currently, this requires fetching full subject progress and extracting lesson data client-side. This endpoint provides a focused, fast response for topic-level lesson lists.

Output: New endpoint returning lesson completion status with <5ms response time regardless of lesson count (leveraging existing bitmap infrastructure and Redis pipeline GETBIT).
</objective>

<task type="auto">
  <name>Task 2: Add Topic Lessons Endpoint</name>
  <files>fastapi_app/api/v1/endpoints/progress.py</files>
  <action>
Add `GET /{subject}/topics/{topic_id}/lessons` endpoint following existing granular endpoint patterns.

**CRITICAL ROUTE ORDER:** This endpoint MUST be defined BEFORE the `/{subject}` catch-all route (around line 829). Place it after the `get_unit_detail` endpoint (after line 826) and before the `get_subject_progress` endpoint.

Implementation steps:

1. Add helper function `find_topic_in_hierarchy(hierarchy: SubjectHierarchy, topic_id: str) -> TopicInfo | None`:
   - Traverse tracks -> units -> topics
   - Return TopicInfo if found, None otherwise
   - Place near other helper functions (after `_is_topic_unlocked`)

2. Add endpoint `get_topic_lessons`:
   - Route: `@router.get("/{subject}/topics/{topic_id}/lessons", response_model=TopicLessonsResponse)`
   - Parameters: subject, topic_id, user (CurrentUser), hierarchy_service, access_service, progress_service
   - Logic:
     a. Get cached hierarchy via `hierarchy_service.get_hierarchy(subject)`
     b. Return 404 if subject not found
     c. Find topic using `find_topic_in_hierarchy()`
     d. Return 404 with code "TOPIC_NOT_FOUND" if topic not found
     e. Check access via `access_service.check_access_with_plan()` (same pattern as existing endpoints)
     f. Return 403 with "NO_ACCESS" if no access AND no free content
     g. Use Redis pipeline for batch GETBIT:
        - Build key: `memora:progress:{user.sub}:{subject}:v{hierarchy.version}`
        - Pipeline GETBIT for each lesson's bit_index
        - Execute pipeline
     h. Build and return TopicLessonsResponse with lesson statuses

3. Add import for `TopicLessonsResponse` and `LessonCompletionStatus` from models

**Performance notes:**
- Do NOT load full bitmap with `get_completed_bits()` - use targeted GETBIT via pipeline
- Access Redis via `progress_service.redis` (existing pattern)
- Total time target: <5ms (hierarchy ~0.5ms, topic lookup ~0.2ms, access ~0.5ms, pipeline GETBIT ~1ms)
  </action>
