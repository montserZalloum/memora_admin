<objective>
Fix two confirmed bugs in the FSRS processor and add next_review date clamping, then create the composite database index for review query performance.

Purpose: The existing fsrs_processor.py has two bugs that create incorrect Memory State records: (1) it never checks `is_reviewable` on the lesson, creating states for non-reviewable lessons, and (2) it compares `stage_id` against `stage_title` for skippable filtering, which never matches because they're different value types. Additionally, `next_review` must be clamped to midnight with minimum tomorrow to prevent same-day reviews. The composite index is needed for <5ms review queries at scale.

Output: A corrected fsrs_processor.py and a composite index on the Memora Memory State table.
</objective>

  ```python
      stages = frappe.get_all(
          "Memora Lesson Stage Settings",
  ```

  ```python
  # Look up stage_type from the lesson's child table (Memora Lesson Stage)
  # The child table's stage_title field holds the stage identifier (same as stage_id in interactions)
  # The child table's stage_type field links to Memora Lesson Stage Settings
  stage_row = frappe.db.get_value(
      "Memora Lesson Stage",
      {"parent": lesson, "stage_title": stage_id},
      ["stage_type", "is_skippable"],
      as_dict=True,
  )

  if stage_row:
      # Per-stage override takes priority over global setting
      if stage_row.is_skippable:

          continue
      # Fall back to global setting from stage type
      if stage_row.stage_type in skippable_types:
          skipped += 1
          continue
  ```
