Rewrite the FSRS processor to create/update Memory States per item instead of per stage. Use the new BIGINT PK (via sequence), BINARY(16) item_id (via UUID_TO_BIN polyfill), and season_seq for partition routing. Maintain backward compatibility for interactions without item_id.

Purpose: This is the core FSRS logic change -- shifting from "1 Memory State per stage" to "1 Memory State per item within a stage." Without this, item-level spaced repetition does not work.
Output: Rewritten fsrs_processor.py with item-level processing.

    **Modify `_get_active_season()` to return both season name AND season_seq:**
    ```python
    def _get_active_season() -> tuple[str, int] | None:
        """Get the currently active season ID and seq number.
        Returns (season_name, season_seq) or None.
        """
        today = date.today()
        result = frappe.db.get_value(
            "Memora Season",
            {
                "is_published": 1,
                "start_date": ["<=", today],
                "end_date": [">=", today],
            },
            ["name", "season_seq"],
            as_dict=True,
        )
        if result and result.season_seq:
            return (result.name, result.season_seq)
        return None
    ```

    **Rewrite `process_fsrs_reviews()` main logic:**

    1. Call `_get_active_season()` and unpack to `(active_season, active_season_seq)`. If None, return early.

    2. Query interactions -- add `item_id` to the fields list:
       ```python
       interactions = frappe.get_all(
           "Memora Interaction Log",
           filters={
               "event_type": "Completed",
               "creation": [">=", cutoff],
           },
           fields=["player", "lesson", "stage_id", "item_id", "errors_count", "time_spent", "creation"],
           order_by="creation asc",
           limit_page_length=500,
       )
       ```

    3. For each interaction, after the skippable/reviewable checks:
       - **If `interaction.item_id` is present (non-empty string):**
         Process as item-level. The item_id from the Interaction Log is a UUID string.
         - Idempotency key: `f"memora:fsrs:processed:{player}:{item_id}:{interaction.creation}"`
         - Lookup existing Memory State via raw SQL (because item_id is BINARY(16)):
           ```python
           existing = frappe.db.sql("""
               SELECT name, stability, difficulty, next_review
               FROM `tabMemora Memory State`
               WHERE player = %(player)s
                 AND item_id = UUID_TO_BIN(%(item_id)s)
                 AND season_seq = %(season_seq)s
               LIMIT 1
           """, {
               "player": player,
               "item_id": item_id,
               "season_seq": active_season_seq,
           }, as_dict=True)
           ```
         - If existing: update via `frappe.db.sql()`:
           ```python
           frappe.db.sql("""
               UPDATE `tabMemora Memory State`
               SET stability = %(stability)s,
                   difficulty = %(difficulty)s,
                   next_review = %(next_review)s,
                   modified = NOW(6)
               WHERE name = %(name)s
                 AND season_seq = %(season_seq)s
           """, {
               "name": existing[0].name,
               "season_seq": active_season_seq,
               "stability": card.stability,
               "difficulty": card.difficulty,
               "next_review": next_review_naive,
           })
           ```
         - If not existing: INSERT via raw SQL with sequence value:
           ```python
           next_name = frappe.db.get_next_sequence_val("Memora Memory State")
           frappe.db.sql("""
               INSERT INTO `tabMemora Memory State`
               (name, season_seq, subject, player, item_id, stage_id, lesson,
                stability, difficulty, next_review,
                creation, modified, owner, modified_by, docstatus, idx)
               VALUES
               (%(name)s, %(season_seq)s, %(subject)s, %(player)s,
                UUID_TO_BIN(%(item_id)s), %(stage_id)s, %(lesson)s,
                %(stability)s, %(difficulty)s, %(next_review)s,
                NOW(6), NOW(6), 'Administrator', 'Administrator', 0, 0)
           """, {
               "name": next_name,
               "season_seq": active_season_seq,
               "subject": subject,
               "player": player,
               "item_id": item_id,
               "stage_id": stage_id,
               "lesson": lesson,
               "stability": card.stability,
               "difficulty": card.difficulty,
               "next_review": next_review_naive,
           })
           ```
         - Redis cache key: `f"memora:fsrs:{player}:{item_id}"` (uses item_id not stage_id)

       - **If `interaction.item_id` is empty/None (legacy):**
         Fall back to stage-level processing. This handles old interactions that were created before the item-level update. Use the same raw SQL pattern but with a different lookup:
         ```python
         existing = frappe.db.sql("""
             SELECT name, stability, difficulty, next_review
             FROM `tabMemora Memory State`
             WHERE player = %(player)s
               AND stage_id = %(stage_id)s
               AND season_seq = %(season_seq)s
               AND item_id IS NULL
             LIMIT 1
         """, ...)
         ```
         For INSERT, set `item_id` to NULL (raw SQL: remove the UUID_TO_BIN call, use NULL directly).
         Actually, since item_id is NOT NULL (BINARY(16)), for legacy stage-level processing, generate a deterministic "fake" item_id from the stage_id so it's consistent across reruns:
         ```python
         import uuid
         # Deterministic UUID from stage_id (consistent across reruns)
         legacy_item_id = str(uuid.uuid5(uuid.NAMESPACE_OID, stage_id))
         ```
         Then use this `legacy_item_id` for the lookup and insert. This ensures backward compatibility while maintaining the NOT NULL constraint on item_id.

    4. After processing, commit if any records were modified. Keep existing error handling and logging patterns.

    **Key differences from old code:**

    - Lookup by `(player, item_id, season_seq)` not by name
    - Redis cache key uses item_id not stage_id
    - Idempotency key uses item_id not stage_id
