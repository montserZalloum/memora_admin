<objective>
Fix skippable stage types generating unnecessary item_id UUIDs and build generators reporting incorrect is_skippable values.

Purpose: Skippable stages (SENTENCE_BUILDER, MINDMAP, etc.) are excluded from FSRS tracking. Generating item_ids for them wastes storage, confuses the data model, and sends misleading information to the player app. The build generators also output is_skippable=false for these stages because they only read the per-stage override (always 0) and miss the global Memora Lesson Stage Settings fallback.

Output: Three files fixed so that (1) the editor skips item_id generation for effectively-skippable stages, (2) build generators resolve is_skippable with the same two-tier logic the FSRS processor already uses.
</objective>

  <files>memora_admin/public/js/game_lesson.js</files>
  <action>
The editor currently calls `generateItemUUID()` unconditionally for all stage sub-elements in all 4 dialog save handlers. Fix it so item_ids are only generated for non-skippable stages.

**How to determine effective is_skippable:**

The `row` object (passed to each `open_*_dialog` function) comes from `locals[cdt][cdn]` in the `edit_content_btn` handler. It has:
- `row.is_skippable` (per-stage override, 0 or 1)
- `row.stage_type` (Link to "Memora Lesson Stage Settings", e.g. "SENTENCE_BUILDER")

Two-tier resolution (same logic as FSRS processor):
1. If `row.is_skippable` is truthy (1), stage IS skippable (per-stage override wins)
2. Else, look up the global setting from `Memora Lesson Stage Settings` where name = `row.stage_type`

**Implementation approach:**

1. Add an async helper function `isEffectivelySkippable(row)` that:
   - Returns `true` immediately if `row.is_skippable` is truthy
   - Otherwise calls `frappe.db.get_value("Memora Lesson Stage Settings", row.stage_type, "is_skippable")` (this is Frappe's client-side async DB call, returns a Promise)
   - Returns `true` if the global setting has `is_skippable=1`, else `false`

2. Modify the `edit_content_btn` handler to resolve skippable status BEFORE opening the dialog:
   - After computing `config_json` but before the `if/else if` chain, call `isEffectivelySkippable(row)` and pass the result as a parameter to each `open_*_dialog` function
   - Add a `skipItemIds` parameter (boolean) to each `open_*_dialog` function signature

3. In each dialog's `primary_action` save handler, conditionally generate item_ids:
   - **MATCHING** (line 105): Change `item_id: p.item_id || generateItemUUID()` to only include `item_id` key if `!skipItemIds`. When skippable, omit the `item_id` field entirely from the pair object (or set to null).
   - **REVEAL** (line 182): Same pattern for `h.item_id || generateItemUUID()`
   - **SENTENCE_BUILDER** (line 260): Same pattern for `row.item_id || generateItemUUID()`. When skippable, write words as `{text: row.item_1}` without item_id.
   - **MINDMAP** (lines 385, 398): Same pattern for branch and item nodes.

4. When `skipItemIds` is true and there are existing item_ids in the loaded data, they should be STRIPPED on save (not preserved). This ensures re-saving a previously-broken skippable stage removes the stale item_ids.

**Important: Do NOT use `frappe.call` with a whitelisted method.** Use `frappe.db.get_value` which is the standard Frappe client-side DB access. The call pattern is:
```javascript
let settings = await frappe.db.get_value("Memora Lesson Stage Settings", row.stage_type, "is_skippable");
// settings.message.is_skippable will be 0 or 1
```

**Existing data backward compat:** The `existing_data` loading code in each dialog already uses `p.item_id || null` / `h.item_id || null` etc. This is fine -- loaded data shows whatever was stored. The cleanup happens on save.

Both `generator.py` (`_generate_lesson_json` at line 274) and `plan_generator.py` (`_generate_lesson_json` at line 542) currently output:
```python
"is_skippable": bool(stage.is_skippable),
```
This only reads the per-stage override field (always 0 for existing data). It must resolve effective is_skippable using the same two-tier logic as the FSRS processor.

**Implementation for both files:**

1. Add a helper function `_get_skippable_stage_types()` (same as in `fsrs_processor.py` lines 42-49):
```python
def _get_skippable_stage_types() -> set[str]:
    """Get set of stage type names where is_skippable=1 globally."""
    stages = frappe.get_all(
        "Memora Lesson Stage Settings",
        filters={"is_skippable": 1},
        fields=["stage_title"],
    )
    return {s.stage_title for s in stages}
```

2. In each file's `_generate_lesson_json` function, call `_get_skippable_stage_types()` ONCE before the stage loop (not inside the loop).

3. Replace the is_skippable line with two-tier resolution:
```python
# Per-stage override takes priority, then fall back to global stage type setting
effective_skippable = bool(stage.is_skippable) or (stage.stage_type in skippable_types)
```

4. Use `effective_skippable` in the stage_data dict:
```python
"is_skippable": effective_skippable,
```

5. Additionally, when `effective_skippable` is True, strip `item_id` keys from the config dict to keep the build output clean:
```python
config = _parse_stage_config(stage.config_json)
if effective_skippable:
    _strip_item_ids(config)
```

6. Add a `_strip_item_ids(config: dict)` helper that recursively removes `item_id` keys from the config structure. The config shapes are:
   - MATCHING: `{"pairs": [{"item_id": ..., "right": ..., "left": ...}, ...]}`
   - REVEAL: `{"highlights": [{"item_id": ..., "word": ..., "explanation": ...}, ...]}`
   - SENTENCE_BUILDER: `{"words": [{"item_id": ..., "text": ...}, ...]}`
   - MINDMAP: `{"children": [{"item_id": ..., "label": ..., "children": [{"item_id": ..., ...}]}, ...]}`

   The simplest approach: iterate all lists in the config dict, and for each dict item in those lists, pop "item_id" if present. For MINDMAP, recurse into nested "children" arrays.

   ```python
   def _strip_item_ids(config: dict) -> None:
       """Remove item_id keys from config when stage is skippable."""
       for key, value in config.items():
           if isinstance(value, list):
               for item in value:
                   if isinstance(item, dict):
                       item.pop("item_id", None)
                       # Recurse for nested children (MINDMAP)
                       if "children" in item and isinstance(item["children"], list):
                           for child in item["children"]:
                               if isinstance(child, dict):
                                   child.pop("item_id", None)
   ```

**Apply identical changes to BOTH files.** They have duplicate `_generate_lesson_json` functions -- this is the existing pattern, keep it.

**Performance note:** `_get_skippable_stage_types()` uses `frappe.get_all` which is fast and cacheable. It's called once per lesson generation, not per stage. This is the same approach the FSRS processor uses.
