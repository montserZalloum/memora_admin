<objective>
Create three whitelisted Frappe API functions (verify_player_password, register_player, set_player_password) that let FastAPI verify player passwords, register new players, and manage passwords -- all without creating Frappe sessions. Add a "Reset Password" button to the Player Profile Desk form that calls set_player_password.

Purpose: This is the bridge layer between the FastAPI sidecar and Frappe's password infrastructure. FastAPI calls these APIs via FrappeClient (API key auth). All three use allow_guest=False to prevent direct unauthenticated access. The DocType's password hashing infrastructure from Phase 29 handles PBKDF2-SHA256 storage automatically.

Output: `memora_admin/api/auth.py` with 3 whitelisted functions + 3 helpers, updated `memora_player_profile.js` with Reset Password button.
</objective>

<task type="auto">
  <name>Task 1: Create Frappe auth API with three whitelisted functions</name>
  <files>memora_admin/api/auth.py</files>
  <action>
Create `memora_admin/api/auth.py` with three whitelisted functions and three helper functions. All three API functions use `@frappe.whitelist(allow_guest=False)` -- they are called by FastAPI via FrappeClient with API key auth.

**1. `verify_player_password(mobile: str, password: str) -> dict`**
- Normalize phone: `re.sub(r"[^\d]", "", mobile)`, validate with `MOBILE_PATTERN = re.compile(r"^\d{9,15}$")`
- Resolve mobile to docname: `frappe.db.get_value("Memora Player Profile", {"mobile": mobile}, "name")`
- If not found: `frappe.throw("Invalid credentials", frappe.AuthenticationError)` -- SAME error as wrong password (anti-enumeration per CONTEXT.md)
- Verify: `check_password(player_name, password, doctype="Memora Player Profile", fieldname="password")` from `frappe.utils.password`
- On AuthenticationError: `frappe.throw("Invalid credentials", frappe.AuthenticationError)` -- SAME generic error
- On success: fetch profile via `frappe.get_doc("Memora Player Profile", player_name)` and fetch XP from Redis wallet via `_get_player_xp(player_name)`
- Return dict with keys: `player_id` (profile.name), `display_name`, `plan`, `avatar`, `gender`, `mobile`, `xp` (int, from Redis wallet -- per CONTEXT.md locked decision: same profile data bundle as existing login flow including XP)
- CRITICAL: Always resolve mobile->docname FIRST. The __Auth table keys by docname (PLAYER-00001), not phone number. Calling check_password with mobile directly will ALWAYS fail.
- This function does NOT create a Frappe session -- it just verifies and returns data.

**2. `register_player(mobile, password, plan, grade, major, season, display_name=None, avatar=None, gender=None) -> dict`**
- Normalize phone same as verify
- Check uniqueness: `frappe.db.exists("Memora Player Profile", {"mobile": mobile})` -- if exists, `frappe.throw("Phone already registered", frappe.DuplicateEntryError)` (specific error is safe per CONTEXT.md -- OTP verified before register is called)
- Default display_name if not provided: Arabic pattern "لاعب {N}" where N = `frappe.db.count("Memora Player Profile") + 1`
- Default avatar if not provided: "pre" (first option in the Select field)
- Create doc via `frappe.get_doc({...})` with all fields, then `doc.insert(ignore_permissions=True)` -- the DocType's __setup__/validate/after_insert hooks handle password hashing (PBKDF2-SHA256) and wallet creation automatically
- After insert, call `_initialize_redis_wallet(doc.name)` to seed Redis wallet (player fully ready after register per CONTEXT.md)
- Return same profile dict shape as verify: `player_id`, `display_name`, `plan`, `avatar`, `gender`, `mobile`, `xp` (always 0 for new registrations since wallet was just initialized)

**3. `set_player_password(player_name: str, new_password: str) -> dict`**
- Validate player exists: `frappe.db.exists("Memora Player Profile", player_name)` -- if not, `frappe.throw("Player not found", frappe.DoesNotExistError)`
- Validate password policy: `len(new_password) < 8` -> `frappe.throw("Password must be at least 8 characters", frappe.ValidationError)`
- Update hash: `update_password(player_name, new_password, doctype="Memora Player Profile", fieldname="password")` from `frappe.utils.password`
- Invalidate sessions: call `_invalidate_player_sessions(player_name)`
- Return `{"success": True, "player_name": player_name}`

**Helper: `_get_player_xp(player_name: str) -> int`**
- Import `get_fastapi_redis` from `memora_admin.events.access_sync`
- Read XP from Redis: `r.hget(f"memora:wallet:{player_name}", "xp")`
- Return `int(xp_value)` if found, else `0` (wallet may not exist yet or Redis may be cold -- default to 0 which is consistent with self-healing pattern)
- Wrap in try/except -- return 0 on Redis failure (non-fatal)

**Helper: `_initialize_redis_wallet(player_name: str) -> None`**
- Import `get_fastapi_redis` from `memora_admin.events.access_sync`
- Set `memora:wallet:{player_name}` hash with `{"xp": 0, "streak": 0}` via `r.hset(wallet_key, mapping=...)`
- Wrap in try/except -- non-fatal, wallet will self-heal via ensure_hydrated() on first API call
- Log warning on failure via `frappe.logger()`

**Helper: `_invalidate_player_sessions(player_name: str) -> None`**
- Import `get_fastapi_redis` from `memora_admin.events.access_sync`
- Delete session key: `r.delete(f"memora:session:{player_name}")` -- same pattern as `devices.py:148`
- Log info on success, log error on failure (non-fatal -- sessions expire naturally via TTL)
- Wrap in try/except

**Style requirements:** Use tabs for indentation, double quotes, 110 char line length per Ruff config. Import `re` and `frappe` at top level; import `check_password`, `update_password`, and `get_fastapi_redis` inside functions (lazy imports to avoid circular imports and keep module lightweight).

  <action>
Add a "Reset Password" custom button to the Player Profile form's Actions menu. This button opens a dialog for the admin to set a new password, then calls `set_player_password` which handles both hashing and session invalidation.

In the existing `refresh` handler (after the `frm.is_new()` guard and before the device sync block), add:

```javascript
frm.add_custom_button(__("Reset Password"), function() {
    let dialog = new frappe.ui.Dialog({
        title: __("Reset Player Password"),
        fields: [
            {
                fieldname: "new_password",
                fieldtype: "Password",
                label: __("New Password"),
                reqd: 1,
                description: __("Minimum 8 characters"),
            },
            {
                fieldname: "confirm_password",
                fieldtype: "Password",
                label: __("Confirm Password"),
                reqd: 1,
            },
        ],
        primary_action_label: __("Reset Password"),
        primary_action: function(values) {
            if (values.new_password !== values.confirm_password) {
                frappe.msgprint(__("Passwords do not match"));
                return;
            }
            if (values.new_password.length < 8) {
                frappe.msgprint(__("Password must be at least 8 characters"));
                return;
            }
            frappe.call({
                method: "memora_admin.api.auth.set_player_password",
                args: {
                    player_name: frm.doc.name,
                    new_password: values.new_password,
                },
                freeze: true,
                freeze_message: __("Resetting password..."),
                callback: function(r) {
                    if (r.message && r.message.success) {
                        dialog.hide();
                        frappe.show_alert({
                            message: __("Password reset. Player will be logged out."),
                            indicator: "green",
                        });
                    }
                },
            });
        },
    });
    dialog.show();
}, __("Actions"));
```

This follows the exact same pattern as the existing "Grant Access" button (also in `__("Actions")` group). The dialog validates:
1. Passwords match (client-side)
2. Minimum 8 characters (client-side, also enforced server-side)

On success, shows green alert confirming password reset and session invalidation.

**Important:** Place the button code AFTER the existing "Grant Access" button and BEFORE the device sync block. Both buttons should be under the same `__("Actions")` group.
