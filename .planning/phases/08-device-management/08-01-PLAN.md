<task type="auto">
  <name>Task 3: Create DeviceService with Lua script</name>
  <files>fastapi_app/services/device.py</files>
  <action>
Create DeviceService class for atomic device registration:

1. **Lua script constant** `REGISTER_DEVICE_SCRIPT`:
   - KEYS[1] = device registry key (memora:devices:{user_id})
   - ARGV[1-7] = device_id, device_name, user_agent, platform, timestamp, max_devices, fingerprint
   - Logic flow:
     a. Check if device_id already exists -> update last_login, return {1, device_id, "existing"}
     b. Scan all fields for fingerprint match -> if match, replace old UUID with new, return {1, device_id, "fingerprint_match"}
     c. Count devices (fields matching `device:*:fingerprint`)
     d. If count >= max_devices -> return {0, "", "limit_exceeded", count, max_devices}
     e. Otherwise register new device, return {1, device_id, "new"}

2. **DeviceService class** with:
   - `__init__(self, redis_client, key_prefix="memora:")` - store redis client and prefix
   - `_device_key(self, user_id)` - returns `{prefix}devices:{user_id}`
   - `_get_register_script()` - lazy-load and cache the Lua script
   - `_generate_fingerprint(self, user_agent)` - parse UA with user-agents library, return stable fingerprint string (device_family:brand:os_family:browser_family) without version numbers
   - `_extract_device_info(self, user_agent, platform_hint)` - parse UA to extract device_name, platform, user_agent, fingerprint
   - `register_device(self, user_id, device_id, user_agent, max_devices, platform_hint=None)` -> DeviceRegistrationResult
   - `get_devices(self, user_id)` -> list[DeviceInfo] - parse Redis hash fields into device objects
   - `remove_device(self, user_id, device_id)` -> bool - remove device fields from hash
   - `validate_device(self, user_id, device_id)` -> bool - check if device exists (HEXISTS)

3. **Fingerprint generation strategy**:
   - Parse user_agent with `user_agents.parse()`
   - Extract stable components: device.family, device.brand, os.family, browser.family (NO versions)
   - Join non-empty components with ":" as separator
   - This handles browser updates gracefully (version changes don't create new fingerprints)

4. **Device name generation**:
   - If device has family and it's not "Other": use device info
   - If device has brand and model: "{brand} {model}"
   - Otherwise use browser family
   - Append " / {os_family} {os_version}" for full name
   - Examples: "iPhone / iOS 17.0", "Chrome / Windows 10", "Samsung Galaxy S23 / Android 14"

5. **Redis hash structure** (per RESEARCH.md):
   - Key: `memora:devices:{user_id}`
   - Fields per device:
     - `device:{device_id}:name` -> device name
     - `device:{device_id}:ua` -> full user agent
     - `device:{device_id}:platform` -> iOS/Android/Web
     - `device:{device_id}:last_login` -> ISO timestamp
     - `device:{device_id}:fingerprint` -> stable fingerprint
     - `device:{device_id}:push_token` -> optional push token

Use structlog for logging (logger = structlog.get_logger()). Log device_registered on success, device_limit_exceeded on failure.

Follow existing service patterns (see session.py, settings.py for reference).
