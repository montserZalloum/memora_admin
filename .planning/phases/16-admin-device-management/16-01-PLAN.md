  <name>Task 1: Create whitelisted device APIs</name>
  <files>memora_admin/api/devices.py</files>
  <action>
Create `memora_admin/api/devices.py` with two whitelisted Frappe APIs:

**1. `sync_devices_from_redis(player_name)`:**
- Import `get_fastapi_redis` from `memora_admin.events.access_sync`
- Accept `player_name` (Memora Player Profile docname)
- Get user_id from profile's `user` field
- Connect to Redis via `get_fastapi_redis()` (NOT `frappe.cache()`)
- Read `memora:devices:{user_id}` hash via `r.hgetall(devices_key)`
- Parse hash fields using DeviceService pattern:
  - Field format: `device:{id}:{attr}` where attr is name, ua, platform, last_login, fingerprint, push_token
  - Map `name` -> `device_name`, `ua` -> `user_agent`, rest as-is
- Clear existing `authorized_devices` child table: `profile.authorized_devices = []`
- Append each parsed device to child table with fields: device_id, device_name, platform, last_login, user_agent, push_token
- Save with `profile.save(ignore_permissions=True)`
- Return list of device dicts (for JS callback)
- Wrap Redis operations in try/except; on `redis.ConnectionError` or `redis.RedisError`, raise `frappe.throw("Could not fetch live device data", title="Redis Error")`

**2. `remove_device(player_name, device_id)`:**
- Accept `player_name` and `device_id`
- Get user_id from profile's `user` field
- Connect to Redis via `get_fastapi_redis()`
- Build field list for deletion: `device:{device_id}:name`, `device:{device_id}:ua`, `device:{device_id}:platform`, `device:{device_id}:last_login`, `device:{device_id}:fingerprint`, `device:{device_id}:push_token`
- Call `r.hdel(devices_key, *fields)` -- standard redis.Redis supports multi-field hdel
- Invalidate session: `r.delete(f"memora:session:{user_id}")`
- Return `{"success": deleted > 0, "device_id": device_id}`
- Wrap in try/except for Redis errors

Both functions decorated with `@frappe.whitelist()`.

**Fix `memora_admin/events/device_sync.py`:**
Replace the existing `on_player_profile_update` function to fix three critical bugs:

1. **Bug: `frappe.cache()` namespace mismatch** -- Replace `cache = frappe.cache()` with `r = get_fastapi_redis()` (import from `memora_admin.events.access_sync`).

2. **Bug: `cache.hdel()` single-field signature** -- The standard `redis.Redis.hdel()` from `get_fastapi_redis()` supports `hdel(key, *fields)` properly, so the existing code pattern works once we switch to the correct Redis client.

3. **Bug: `cache.delete_value(session_key)` adds prefix** -- Replace with `r.delete(session_key)` using the `get_fastapi_redis()` connection.

4. **Bug: Early return on empty `authorized_devices`** -- Remove the `if not doc.authorized_devices: return` guard at line 20. This should NOT skip sync when all devices have been removed.

The fixed function should:
- Import `get_fastapi_redis` from `memora_admin.events.access_sync`
- Use `r = get_fastapi_redis()` for all Redis operations
- Use `r.hdel(devices_key, *fields_to_delete)` for device removal
- Use `r.delete(session_key)` for session invalidation
- Handle the case where `doc.authorized_devices` is empty (all devices removed) -- still proceed with removal logic
- Wrap Redis operations in try/except to log errors without breaking the save

**Note on hooks.py:** The existing `on_update` hook for `Memora Player Profile` includes `device_sync.on_player_profile_update`. Keep this registration -- it serves as a safety net if an admin manually deletes child table rows and saves. The primary removal flow is via the `remove_device` API, but the hook catches edge cases. No changes needed to `hooks.py` -- keep the existing registration.

Actually, on reflection, the hooks.py registration is already correct. Only `device_sync.py` needs fixing.
