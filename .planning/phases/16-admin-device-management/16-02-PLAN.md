**In the `refresh` handler (after the existing Grant Access button):**

1. **Make child table read-only:** Call `frm.set_df_property("authorized_devices", "read_only", 1)` so admin cannot hand-edit device data. Per CONTEXT.md: all fields are read-only, data comes from Redis sync only.

2. **Sync devices from Redis:** Call `frappe.call` to `memora_admin.api.devices.sync_devices_from_redis` with `player_name: frm.doc.name`. On success callback:
   - Call `frm.reload_doc()` to refresh the form with the saved child table data (the API saves server-side). Use `frm.reload_doc()` rather than just `frm.refresh_field()` to avoid the dirty state issue (Pitfall 6 from research).
   - Note: `frm.reload_doc()` will re-trigger `refresh`, but the sync call is idempotent so this is safe. To prevent infinite loop, add a flag: `frm.__device_sync_in_progress`. Set it before the call, check it at the start, and clear it in the callback. If the flag is set, skip the sync call.

3. **Error handling:** On `frappe.call` error callback, show `frappe.msgprint` with red indicator: "Could not fetch live device data. Redis may be unavailable." Per CONTEXT.md: do NOT show stale Frappe data. The child table will remain empty if Redis is down (the API throws an error and doesn't save stale data).

**Sync flow:**
```
form refresh -> check flag -> call sync API -> API reads Redis, saves child table -> reload_doc -> form refresh (flag set, skip sync)
```

  <name>Task 2: Add per-row Remove button with confirmation dialog</name>
  <files>memora_admin/memora_admin/doctype/memora_player_profile/memora_player_profile.js</files>
  <action>
Add per-row "Remove" button to each device row in the authorized_devices child table.

**Implementation approach -- use `frappe.ui.form.on("Memora Player Device", { form_render })` event:**

When each child table row renders, add a small red "Remove" button. The `form_render` event fires for each row when the child table is rendered in editable grid mode.

1. **Add `frappe.ui.form.on("Memora Player Device", { form_render: ... })` handler:**
   - Get the row data: `let row = locals[cdt][cdn]`
   - Get the grid row: `let grid_row = frm.fields_dict.authorized_devices.grid.grid_rows_by_docname[cdn]`
   - Remove any existing button (prevent duplicates on re-render): `grid_row.wrapper.find(".btn-remove-device").remove()`
   - Create button: `$('<button class="btn btn-xs btn-danger btn-remove-device" style="margin-left: 8px;">').text(__("Remove"))`
   - Append button to `grid_row.wrapper.find(".grid-row .row-index")` or similar row element

2. **Button click handler:**
   - Show `frappe.confirm()` dialog: `"Remove {device_name}? Player will be logged out immediately."` (use `row.device_name || row.device_id` for display)
   - On confirm, call `frappe.call` to `memora_admin.api.devices.remove_device` with `player_name: frm.doc.name` and `device_id: row.device_id`
   - Use `freeze: true` and `freeze_message: __("Removing device...")`
   - On success callback (if `r.message && r.message.success`):
     - Show green toast: `frappe.show_alert({ message: __("Device removed successfully"), indicator: "green" })`
     - Call `frm.reload_doc()` to re-trigger sync and refresh the table (the device will be gone from Redis now)
   - On failure: show red toast "Failed to remove device"

3. **Confirmation dialog wording:** Per CONTEXT.md: "Remove [device_name]? Player will be logged out immediately." This is the exact wording specified.

4. **One at a time only:** Per CONTEXT.md, no bulk "Remove All" action. Each button operates on a single row. This is inherently satisfied by per-row buttons.

**Note on editable_grid:** The `Memora Player Device` DocType JSON has `"editable_grid": 1`. Since we set `read_only: 1` on the table in Task 1, the grid rows won't be editable, but the `form_render` event may not fire for read-only grids. If `form_render` doesn't fire, use an alternative approach:

**Alternative (preferred for read-only grids):** Add the Remove buttons in the `refresh` handler after the sync completes, by iterating over `frm.fields_dict.authorized_devices.grid.grid_rows` and appending buttons to each row's wrapper. This approach works regardless of editable_grid setting.

```javascript
// After sync completes and reload_doc runs:
add_remove_buttons(frm);

function add_remove_buttons(frm) {
    let grid = frm.fields_dict.authorized_devices.grid;
    grid.wrapper.find(".btn-remove-device").remove();
    grid.grid_rows.forEach(function(grid_row) {
        if (grid_row.doc && grid_row.doc.device_id) {
            let $btn = $('<button class="btn btn-xs btn-danger btn-remove-device" style="margin: 2px 4px;">')
                .text(__("Remove"))
                .on("click", function() { /* confirm + remove logic */ });
            grid_row.wrapper.find(".rows .data-row .row-index").append($btn);
        }
    });
}
```

Use whichever approach works in Frappe v15. The `form_render` approach is cleaner if it fires; the grid iteration approach is the fallback.
