  <action>
  Create `fastapi_app/services/otp.py` -- new file implementing the OTP lifecycle service.

  **OTPProvider Protocol + StaticOTPProvider:**
  ```python
  @runtime_checkable
  class OTPProvider(Protocol):
      async def send_otp(self, mobile: str, otp: str) -> bool: ...

  class StaticOTPProvider:
      """Dev provider -- always uses '1111', logs instead of sending."""
      async def send_otp(self, mobile: str, otp: str) -> bool:
          logger.info("otp_sent_static", mobile_suffix=mobile[-4:])
          return True
  ```

  **OTPService class:**
  - Constructor: `__init__(self, redis_client, provider=None, key_prefix="memora:")`
  - If provider is None, default to StaticOTPProvider()

  Constants:
  - OTP_TTL = 300 (5 minutes)
  - RESET_TOKEN_TTL = 900 (15 minutes)
  - MAX_ATTEMPTS = 3
  - COOLDOWN_TTL = 60 (60s resend cooldown)
  - RATE_LIMIT_WINDOW = 600 (10 min)
  - PHONE_LIMIT = 3 (3 OTP/phone/10min)
  - IP_LIMIT = 10 (10 OTP/IP/10min)

  **Methods to implement:**

  1. `async def _check_otp_rate_limit(self, mobile: str, ip_address: str) -> None`
     - Use the same Lua RATE_LIMIT_SCRIPT pattern from `rate_limit.py` (register script, atomic INCR with EXPIRE)
     - Check `{prefix}ratelimit:otp:phone:{mobile}` against PHONE_LIMIT
     - Check `{prefix}ratelimit:otp:ip:{ip_address}` against IP_LIMIT
     - Raise HTTPException(429) with `detail` and `retry_after` if exceeded
     - Use RATE_LIMIT_WINDOW (600s) for both keys

  2. `async def _check_cooldown(self, mobile: str) -> None`
     - Check `{prefix}ratelimit:otp:cooldown:{mobile}` exists
     - If exists, get TTL and raise HTTPException(429, detail="Please wait before requesting another OTP", retry_after=ttl)

  3. `async def _set_cooldown(self, mobile: str) -> None`
     - Set `{prefix}ratelimit:otp:cooldown:{mobile}` = "1" with ex=COOLDOWN_TTL

  4. `async def create_pending_registration(self, mobile, password, display_name, gender, grade, plan, major, ip_address) -> str`
     - Call _check_otp_rate_limit and _check_cooldown
     - Phone reservation: `redis.set(f"{prefix}phone_reserved:{mobile}", "1", ex=OTP_TTL, nx=True)` -- if not reserved, raise HTTPException(409, "Phone number has a pending registration")
     - Generate OTP via provider (StaticOTPProvider always returns True, OTP is always "1111" for now)
     - Store pending state as JSON in `{prefix}pending:{pending_id}` with ex=OTP_TTL. pending_id = secrets.token_urlsafe(32)
     - JSON contains: mobile, password, display_name, gender, grade, plan, major, otp ("1111"), attempts (0)
     - Set cooldown
     - Return pending_id

  5. `async def verify_registration_otp(self, pending_id: str, otp: str) -> dict`
     - Get `{prefix}pending:{pending_id}` -- if None, raise HTTPException(401, "OTP expired or invalid")
     - Parse JSON, check attempts >= MAX_ATTEMPTS -- if so, delete key + phone reservation, raise HTTPException(401, "Too many attempts. Please request a new OTP.")
     - Compare otp -- if mismatch, increment attempts, set with keepttl=True, raise HTTPException(401) with detail dict: {"detail": "Invalid OTP", "remaining_attempts": remaining}
     - On match: delete pending key + phone reservation, return parsed data dict (contains all registration fields)

  6. `async def resend_registration_otp(self, pending_id: str, ip_address: str) -> None`
     - Get pending data from Redis -- if None, raise HTTPException(401, "Registration expired")
     - Parse JSON, extract mobile
     - Check cooldown and rate limit
     - Generate new OTP (still "1111"), update pending data with new OTP and reset attempts to 0
     - Set with keepttl=True (preserve original TTL)
     - Set new cooldown
     - Call provider.send_otp

  7. `async def create_password_reset(self, mobile: str, ip_address: str) -> None`
     - Check rate limit and cooldown
     - Generate OTP, store in `{prefix}reset:{mobile}` as JSON: {"otp": "1111", "attempts": 0}, ex=OTP_TTL
     - Set cooldown
     - Call provider.send_otp
     - NOTE: This method does NOT verify the phone exists in DB -- the endpoint does that check before calling this, BUT per anti-enumeration: the endpoint returns a generic success message regardless. So this method is called regardless (no user enumeration via timing).

  8. `async def verify_password_reset_otp(self, mobile: str, otp: str) -> str`
     - Get `{prefix}reset:{mobile}` -- if None, raise HTTPException(401, "OTP expired or invalid")
     - Check attempts >= MAX_ATTEMPTS -- delete, raise error
     - Compare OTP -- if mismatch, increment attempts, keepttl, raise with remaining_attempts
     - On match: delete reset key, generate temp token via secrets.token_urlsafe(32)
     - Store `{prefix}reset_token:{token}` = mobile, ex=RESET_TOKEN_TTL
     - Return token

  9. `async def validate_reset_token(self, token: str) -> str`
     - Get `{prefix}reset_token:{token}` -- if None, raise HTTPException(401, "Reset token expired or invalid")
     - Delete the key (single-use)
     - Return mobile number

  Use `structlog.get_logger()` for all logging. Log OTP operations with mobile_suffix (last 4 digits only, never full number).
