  **POST /player/login (PlayerLoginResponse):**

  Follow the EXACT same flow as the current login endpoint but with these changes:

  1. Require X-Device-ID header (unchanged pattern)
  2. Rate limit check using `RateLimiter(redis)` with `target_account=credentials.mobile` (unchanged pattern)
  3. Verify credentials: Call `frappe_client.call("memora_admin.api.auth.verify_player_password", {"mobile": credentials.mobile, "password": credentials.password})`. Catch `FrappeAPIError` -> raise HTTPException(401, "Invalid credentials")
  4. Check profile has plan: `if not profile or not profile.get("plan")` -> 401
  5. Extract `player_id = profile["player_id"]` -- this is the PLAYER-##### docname, used as JWT `sub`
  6. Fetch `session_timeout_days` from SettingsService: `game_settings = await settings_service.get_gamification_settings()`, then `session_ttl_days = game_settings.session_timeout_days` -- use this for session TTL and refresh token expiry (NOT `settings.jwt_refresh_token_expire_days`)
  7. Device registration (unchanged pattern, use `player_id` as user_id)
  8. Wallet fetch for XP (unchanged pattern, use `player_id`)
  9. Session creation: `await session_service.create_session(player_id, plan_id=profile["plan"], ttl_days=session_ttl_days)`
  10. Token creation: `create_access_token(user_id=player_id, mobile=profile["mobile"], plan_id=profile["plan"], display_name=profile.get("display_name", ""), family_id=family_id)` -- note: NO email param, YES mobile param
  11. Refresh token: `create_refresh_token(user_id=player_id, family_id=family_id, expires_delta=timedelta(days=session_ttl_days))`
  12. Return `PlayerLoginResponse` with `LoginProfile(display_name=..., avatar=..., xp=...)` -- NO gender field (dropped per CONTEXT.md)

  **POST /admin/login (TokenResponse):**

  Admin login uses existing FrappeAuthService (kept for admin use only).

  1. NO X-Device-ID required for admin
  2. Rate limit check (same RateLimiter, target_account=credentials.email)
  3. Verify via `FrappeAuthService(settings.frappe_url, settings.frappe_site).verify_credentials(credentials.email, credentials.password)`
  4. If not user -> 401 "Invalid credentials"
  5. Create session (admin uses email as user_id, plan_id can be empty string or "admin")
  6. Token creation: `create_access_token(user_id=user.user_id, email=user.email, plan_id="", display_name=user.full_name, family_id=family_id, role="System Manager")` -- note: YES email, NO mobile
  7. Refresh token with `timedelta(days=settings.jwt_refresh_token_expire_days)` (admin uses .env config, not Memora Settings)
  8. Return `TokenResponse(access_token=..., refresh_token=...)`

  **POST /refresh (TokenResponse):**

  Keep the existing refresh logic but update `create_access_token` call:
  - Pass `email=payload.get("email")` (will be None for player tokens -- that is correct, optional param)
  - Pass `mobile=payload.get("mobile")` (will be None for admin tokens -- that is correct)
  - This makes refresh work for BOTH player and admin tokens transparently
