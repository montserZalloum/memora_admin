Create build worker for processing pending builds:

1. Create `memora_admin/memora_admin/tasks/` directory if not exists
2. Create `tasks/__init__.py` (empty or with module docstring)

3. Create `tasks/build_worker.py`:

   a) Define constants:
      - `RETRY_KEY_PREFIX = "memora:build:retry:"`
      - `MAX_RETRIES = 3`

   b) `process_pending_builds()` - main scheduler entry point:
      - Get all pending builds: `frappe.get_all("Memora Build Queue", filters={"status": "Pending"}, ...)`
      - Order by creation asc (oldest first)
      - For each build, call `_process_single_build(build)` in try/except
      - On exception, call `_mark_build_failed(build.name, str(e))`

   c) `_process_single_build(build: dict)`:
      - Get build doc: `frappe.get_doc("Memora Build Queue", build.name)`
      - Set status to "Processing", started_at to now, save
      - Import and call `generate_subject_json(build.target_name)`
      - Import and call `publish_to_cdn(files, max_retries=3)`
      - If upload succeeds:
        - Set status to "Completed"
        - Set files_generated count
        - Call `_notify_cache_invalidation(build.target_name)`
        - Call `_send_notification(build.target_name, success=True)`
        - Call `_clear_retry_count(build.name)` to clean up Redis key
      - If upload fails:
        - Call `_requeue_build(build_doc)` with retry logic
      - Finally: set completed_at, calculate duration_sec, save

   d) `_notify_cache_invalidation(subject_id: str)`:
      - Publish to Redis channel `memora:cache:invalidate`
      - Message: JSON with `{"type": "hierarchy", "subject_id": ..., "timestamp": ...}`
      - Use `frappe.cache.publish(channel, message)`

   e) `_send_notification(subject_id: str, success: bool, error: str = None)`:
      - Build message based on success/failure
      - Use `frappe.publish_realtime(event="build_complete", message=..., after_commit=True)`

   f) `_mark_build_failed(build_name: str, error: str)`:
      - Load build doc, set status to "Failed", error_message to error, save
      - Call `_clear_retry_count(build_name)` to clean up

   g) `_requeue_build(build_doc)` with Redis-based retry tracking:
      - Build retry key: `RETRY_KEY_PREFIX + build_doc.name`
      - Use `frappe.cache.incr(retry_key)` to increment retry count
      - Get current count: `frappe.cache.get(retry_key)`
      - If count < MAX_RETRIES:
        - Reset status to "Pending" for retry
        - Log retry attempt
      - Else:
        - Mark as "Failed" with error: "Max retries exceeded"
        - Call `_clear_retry_count(build_doc.name)`

   h) `_clear_retry_count(build_name: str)`:
      - Delete Redis key: `frappe.cache.delete(RETRY_KEY_PREFIX + build_name)`

4. Update `hooks.py` with scheduler_events:
   ```python
   scheduler_events = {
       "cron": {
           "*/2 * * * *": [
               "memora_admin.tasks.build_worker.process_pending_builds"
           ]
       }
   }
   ```

Create FastAPI pub/sub listener:

1. Create `fastapi_app/core/pubsub.py`:

   a) Define constant: `INVALIDATION_CHANNEL = "memora:cache:invalidate"`

   b) Create `async def start_pubsub_listener(redis_pool, app_state)`:
      - Create Redis client from pool
      - Create pubsub object: `client.pubsub()`
      - Subscribe to INVALIDATION_CHANNEL
      - Log subscription with structlog
      - Async for loop over `pubsub.listen()`:
        - If message type is "message", call `_handle_invalidation(message["data"], app_state)`
      - Handle CancelledError for clean shutdown
      - Finally: unsubscribe and close client

   c) Create `async def _handle_invalidation(data, app_state)`:
      - Decode data if bytes
      - Parse JSON payload
      - If type is "hierarchy" and subject_id present:
        - Get hierarchy_service from app_state
        - Call `await hierarchy_service.invalidate(subject_id)`
        - Log invalidation with structlog
      - Handle exceptions gracefully (log error, don't crash listener)

2. Update `fastapi_app/main.py` lifespan with explicit wiring steps:

   STEP 1 - Add imports at top of file:
   ```python
   import asyncio
   from fastapi_app.core.pubsub import start_pubsub_listener
   from fastapi_app.services.frappe_client import FrappeClient, FrappeClientSettings
   from fastapi_app.services.hierarchy import HierarchyService
   import redis.asyncio as redis
   ```

   STEP 2 - Inside lifespan, after Redis pool setup (after `app.state.redis_pool = pool`):
   ```python
   # Create Redis client for services
   redis_client = redis.Redis(connection_pool=pool)

   # Create FrappeClient instance
   frappe_settings = FrappeClientSettings()
   frappe_client = FrappeClient(settings=frappe_settings)
   app.state.frappe_client = frappe_client

   # Create HierarchyService instance
   hierarchy_service = HierarchyService(
       redis_client=redis_client,
       frappe_client=frappe_client,
   )
   app.state.hierarchy_service = hierarchy_service

   # Start pub/sub listener background task
   pubsub_task = asyncio.create_task(
       start_pubsub_listener(pool, app.state)
   )
   app.state.pubsub_task = pubsub_task
   ```

   STEP 3 - After yield (cleanup section), add:
   ```python
   # Cancel pub/sub listener
   if hasattr(app.state, 'pubsub_task'):
       app.state.pubsub_task.cancel()
       try:
           await app.state.pubsub_task
       except asyncio.CancelledError:
           pass

   # Close FrappeClient
   if hasattr(app.state, 'frappe_client'):
       await app.state.frappe_client.close()
   ```

The complete wiring chain:
- FrappeClient: Created with FrappeClientSettings (reads from env)
- HierarchyService: Created with redis_client and frappe_client
- Both stored in app.state for access by endpoints and pubsub handler
- Pubsub listener accesses app.state.hierarchy_service for invalidation
