Build the product catalog API endpoint with Redis-cached responses and per-player filtering.

Purpose: Players need to discover purchasable products for their plan. This creates the full data pipeline: Frappe API assembles catalog data from Product Grant + Item Price + Grant Component + Plan Subject, CatalogService caches it per-plan in Redis, and the endpoint applies per-player exclusions (purchased/pending) before returning results.

Output: Working GET /api/v1/catalog endpoint returning filtered product list with sub-100ms cached responses.
</objective>

**Create Frappe whitelisted API** at `memora_admin/memora_admin/api/catalog.py`:

Create `get_plan_catalog(plan_id: str) -> list[dict]` decorated with `@frappe.whitelist(allow_guest=False)`.

Query logic:
1. `frappe.get_all("Memora Product Grant", filters={"plan": plan_id, "is_published": 1}, fields=["name", "item_code"])` — get published grants for the plan
2. For each grant:
   - Get item_name: `frappe.get_value("Item", grant.item_code, "item_name")`
   - Get price: `frappe.get_value("Item Price", {"item_code": grant.item_code, "price_list": "Standard Selling"}, "price_list_rate")` — default to 0.0 if None
   - Get grant components: `frappe.get_all("Memora Grant Component", filters={"parent": grant.name}, fields=["target_doctype", "target_name"])`
   - For each component where `target_doctype == "Memora Subject"`:
     - Get plan subject metadata: `frappe.get_value("Memora Plan Subject", {"parent": plan_id, "subject": comp.target_name}, ["alias_title", "notes"], as_dict=True)`
     - Fall back to subject's own title if Plan Subject entry doesn't exist: `frappe.get_value("Memora Subject", comp.target_name, "title")`
   - Build dict: `{"product_grant_id": grant.name, "bundle_name": item_name, "price": float(price or 0.0), "subjects": [{"subject_id": comp.target_name, "alias_title": ..., "notes": ...}]}`
3. Return list of product dicts

  <action>
**Create CatalogService** at `fastapi_app/services/catalog.py` following the PlanService pattern exactly (`fastapi_app/services/plan.py`).

Constructor: `__init__(self, redis_client: redis.Redis, frappe_client: FrappeClient, key_prefix: str = "memora:")`

**Method 1: `_cache_key(self, plan_id: str) -> str`**
Return `f"{self.prefix}catalog:{plan_id}"`

**Method 2: `async def get_catalog(self, plan_id: str) -> list[CatalogProduct]`**
- Check Redis cache: `await self.redis.get(key)` — if hit, parse JSON and return list of CatalogProduct
- On cache miss: call `await self.frappe.call("memora_admin.api.catalog.get_plan_catalog", {"plan_id": plan_id})`
- Parse result into list[CatalogProduct] via model_validate
- Cache with NO TTL: `await self.redis.set(key, json_str)` (no `ex` parameter — infinite cache per CONTEXT.md decision)
- Return empty list if Frappe returns None/empty
- Handle bytes decoding from Redis (same pattern as PlanService)

**Method 3: `async def get_player_catalog(self, plan_id: str, player_id: str) -> list[CatalogProduct]`**
- Call `self.get_catalog(plan_id)` to get plan-level cached catalog
- Use Redis pipeline to fetch per-player exclusion data in ONE round-trip:
  - `pipe.smembers(f"{self.prefix}access:{player_id}")` — existing access set (subjects player already has)
  - `pipe.smembers(f"{self.prefix}pending:{player_id}")` — pending transaction grants (Phase 22 will populate; empty set for now = show all)
- For each product in catalog:
  - Extract subject_ids from product.subjects
  - Build access keys: `{f"SUB-{s.subject_id}" for s in product.subjects}`
  - Check "purchased": if ALL access keys are in the player's access set, skip product (hide purchased)
  - Check "pending": if `product.product_grant_id` is in the pending set, skip product (hide pending)
  - Otherwise, include product in result
- Return filtered list

**Method 4: `async def invalidate(self, plan_id: str) -> None`**
- Delete cache key: `await self.redis.delete(key)`
- Log with structlog: `logger.info("catalog_cache_invalidated", plan_id=plan_id)`

Use `import json` for serialization. Use `structlog.get_logger(__name__)` for logging. Import `CatalogProduct` from `fastapi_app.models.catalog`.

IMPORTANT: Do NOT use TTL. Cache is infinite, invalidated only by events (Plan 02).
