Output: Complete event-driven cache invalidation pipeline: Frappe hook -> Redis delete + pubsub publish -> FastAPI listener -> CatalogService.invalidate().
</objective>

**Create event handler** at `memora_admin/events/catalog_sync.py` following the `access_sync.py` pattern:

1. Import `frappe`, `json`, and reuse `get_fastapi_redis` from `memora_admin.events.access_sync`
2. Create `on_product_grant_changed(doc, method)`:
   - Get `plan_id = doc.plan`
   - Get Redis connection: `r = get_fastapi_redis()`
   - Direct cache delete (immediate effect): `r.delete(f"memora:catalog:{plan_id}")`
   - Publish pubsub notification for FastAPI sidecar: `r.publish("memora:cache:invalidate", json.dumps({"type": "catalog", "plan_id": plan_id, "timestamp": str(frappe.utils.now())}))`
   - Log: `frappe.logger().info(f"Catalog cache invalidated for plan {plan_id}")`

The direct `r.delete()` ensures immediate cache clear even if the FastAPI pubsub listener has a delay. The pubsub publish ensures the FastAPI in-memory service also invalidates (for any future in-process caching).
