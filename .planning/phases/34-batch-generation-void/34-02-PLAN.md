  <action>
    Create `memora_admin/memora_admin/api/voucher.py` with:

    **1. `generate_batch(batch_name: str)` -- whitelisted method:**

    - Decorated with `@frappe.whitelist()`
    - Validate: batch exists, status is "Draft", quantity > 0, quantity <= 1000, `voucher_hmac_secret` is configured in `frappe.conf`
    - Enqueue the background job:
      ```python
      frappe.enqueue(
          "memora_admin.api.voucher.generate_cards_job",
          batch_name=batch_name,
          queue="default",
          timeout=600,
          job_name=f"voucher_gen_{batch_name}",
          enqueue_after_commit=True,
      )
      ```
    - Return `{"status": "enqueued"}` and show `frappe.msgprint` alert

    **2. `generate_cards_job(batch_name: str)` -- background job function:**

    This is the core generation logic. Must run inside a try/except with full rollback on failure.

    Steps:
    a) Load batch doc: `frappe.get_doc("Memora Voucher Batch", batch_name)`
    b) Read config: `quantity`, `pin_length` (cast to int), `face_value`, and `batch_grants` child table
    c) Get HMAC secret: `frappe.conf.get("voucher_hmac_secret")` -- throw if missing
    d) Build product_names string: join all batch_grants product_grant names with ", "
    e) Reserve serial block: call `reserve_serial_block(quantity)` from generator.py
    f) Generate cards in a loop:
       - For each serial number, call `generate_pin(pin_length)` and `compute_hmac(pin, hmac_secret)`
       - Collect both the bulk_insert row data AND the plaintext PIN data for the export
       - Report progress every 100 cards or on last card: `frappe.publish_progress(percent, title, description)`
    g) Bulk insert all cards using `frappe.db.bulk_insert()`:
       - Fields: `name`, `serial_no`, `pin_hmac`, `batch`, `status`, `owner`, `creation`, `modified`, `modified_by`, `docstatus`
       - Set `name = serial_no` (same value for both -- per research recommendation)
       - Status: "Available"
       - Owner/modified_by: `frappe.session.user` (or "Administrator" in background job context)
       - creation/modified: `frappe.utils.now()`
       - docstatus: 0
       - Use default chunk_size (10,000 -- well above 1,000 max)
    h) Build and encrypt the export CSV:
       - Call `build_export_csv(cards_data, product_names, str(face_value))` where cards_data is list of {"serial_no": serial, "pin": plaintext_pin}
       - Call `create_encrypted_export(csv_bytes, hmac_secret)` to get encrypted bytes
    i) Save encrypted file using `frappe.utils.file_manager.save_file()`:
       - fname: `{batch_name}_pins.enc`
       - content: encrypted bytes
       - dt: "Memora Voucher Batch"
       - dn: batch_name
       - is_private: 1
    j) Update batch:
       - Set `encrypted_file_url` to the file's `file_url`
       - Set `generated_count` to quantity
       - Set `status` to "Generated"
       - Call `batch.save(ignore_permissions=True)`
    k) Commit: `frappe.db.commit()`
    l) Notify admin: `frappe.publish_realtime("batch_generation_complete", {"batch_name": batch_name, "count": quantity})` for client-side notification

    **Error handling (critical):**
    - Wrap the entire generation in try/except
    - On ANY exception: call `frappe.db.rollback()`, then `frappe.publish_realtime("batch_generation_failed", {"batch_name": batch_name, "error": str(e)})`
    - After rollback, re-raise the exception so the RQ job is marked as failed
    - The batch stays in Draft status (rollback undoes everything)
    - The serial numbers are NOT reused (tabSeries counter stays incremented -- gaps are acceptable per user decision)

    **Important anti-patterns to avoid:**
    - Do NOT store plaintext PINs in the database -- only HMAC hashes
    - Do NOT use `random.choice()` -- use `secrets.choice()` via generator.py
    - Do NOT commit inside the loop -- single commit after everything succeeds
    - Do NOT use `frappe.get_doc().insert()` in a loop -- use bulk_insert for all cards at once
  </action>
