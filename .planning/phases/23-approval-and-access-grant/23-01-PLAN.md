  <files>memora_admin/memora_admin/doctype/memora_subscription_transaction/memora_subscription_transaction.py</files>
  <action>
Replace the pass-through Document class with a full implementation:

1. Add `on_update(self)` method that checks `self.has_value_changed("status")` first — do nothing if status unchanged (prevents re-firing on every save).

2. **Approval flow** (status == "Completed"):
   - Call `get_grant_keys(self.related_grant)` from `memora_admin.api.products` to get access keys (e.g., ["SUB-SUBJ-00028"])
   - If no related_grant or no grant keys, `frappe.throw()` with clear error — admin must fix the transaction
   - Look up `expires_at` from the player's plan season: `player.plan -> plan.season -> season.end_date`. Fall back to `2099-12-31` if no season found (matches webhook.py sentinel pattern)
   - Create Player Subscription for each access key using all-or-nothing pattern:
     ```
     created_subs = []
     try:
         for access_key in grant_keys:
             existing = frappe.db.exists("Memora Player Subscription", {"player": self.player, "access_key": access_key})
             if existing:
                 continue  # Skip duplicates (overlapping subscriptions OK per decisions)
             sub = frappe.get_doc({
                 "doctype": "Memora Player Subscription",
                 "player": self.player,
                 "access_key": access_key,
                 "expires_at": expires_at,
                 "is_active": 1,
             })
             sub.insert(ignore_permissions=True)
             created_subs.append(sub.name)
         frappe.db.commit()
     except Exception:
         for sub_name in created_subs:
             frappe.delete_doc("Memora Player Subscription", sub_name, force=True)
         frappe.db.commit()
         frappe.throw("Failed to create subscriptions. Transaction not approved.")
     ```
   - NOTE: Each `sub.insert()` automatically triggers the `on_subscription_change` doc_event hook which does `SADD` to `memora:access:{user_id}` — do NOT manually SADD.
   - After successful subscription creation, SREM from pending set:
     ```
     r = get_fastapi_redis()
     r.srem(f"memora:pending:{self.player}", self.related_grant)
     ```
   - `self.player` IS the user_id (Player Profile has `autoname: field:user`, so the docname is the user email which matches the JWT sub claim used by FastAPI pending set)
   - Log success with `frappe.logger().info(f"Transaction {self.name} approved: {len(created_subs)} subscriptions created")`
   - Show success message to admin: `frappe.msgprint(f"Approved: {len(created_subs)} subscription(s) created for {self.player}", indicator="green")`

3. **Rejection flow** (status == "Rejected"):
   - SREM from pending set (same pattern as approval):
     ```
     r = get_fastapi_redis()
     r.srem(f"memora:pending:{self.player}", self.related_grant)
     ```
   - Log: `frappe.logger().info(f"Transaction {self.name} rejected, pending cleared for {self.player}")`

4. **Catalog cache invalidation is NOT needed** per research finding #3: the catalog data is cached but purchased/pending filtering happens at query time against live Redis sets. The SREM from pending set + SADD to access set (via hook) is sufficient.

5. Imports needed at top of file:
   - `import frappe`
   - `from frappe.model.document import Document`
   - `from memora_admin.api.products import get_grant_keys`
   - `from memora_admin.events.access_sync import get_fastapi_redis`

6. Use `frappe.utils.getdate` for the expires_at date conversion if needed.
