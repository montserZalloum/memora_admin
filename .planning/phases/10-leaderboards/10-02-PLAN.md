   ```python
   """Leaderboard endpoints for XP rankings."""
   from typing import Literal

   import structlog
   from fastapi import APIRouter, Query

   from fastapi_app.api.deps import CurrentUser, LeaderboardServiceDep
   from fastapi_app.models.leaderboard import (
       LeaderboardResponse,
       LeaderboardEntry,
       MyRankResponse,
   )
   ```

2. Create router:
   ```python
   logger = structlog.get_logger()
   router = APIRouter(prefix="/leaderboard", tags=["leaderboard"])
   ```

3. GET /leaderboard/{type} endpoint:
   - Path param: type (Literal["daily", "weekly", "alltime"])
   - Query params:
     - limit: int = Query(10, ge=1, le=100, description="Number of entries to return")
     - subject_id: str | None = Query(None, description="Optional subject filter")
   - Dependencies: CurrentUser (requires auth), LeaderboardServiceDep
   - Implementation:
     - Call leaderboard_service.get_top(type, limit, subject_id)
     - Get total_players via leaderboard_service (or from service method)
     - Build LeaderboardEntry list (note: display_name and avatar_url need player profile lookup - for now return player_id as display_name, None for avatar)
     - Return LeaderboardResponse
   - Log with structlog: leaderboard_fetched event

4. GET /leaderboard/{type}/me endpoint:
   - Path param: type (Literal["daily", "weekly", "alltime"])
   - Query params:
     - subject_id: str | None = Query(None, description="Optional subject filter")
   - Dependencies: CurrentUser, LeaderboardServiceDep
   - Implementation:
     - Call leaderboard_service.get_my_rank(user.sub, type, subject_id)
     - Handle None return (unranked user case is already handled in service)
     - Build MyRankResponse with neighbors as LeaderboardEntry list
   - Log with structlog: my_rank_fetched event

Note: Per CONTEXT.md, display_name and avatar_url come from player profile. For Phase 10, use player_id as display_name placeholder - profile lookup can be added in a future phase.
