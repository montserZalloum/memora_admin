  <action>
1. Update `memora_subscription_transaction.json`:
   - Add "Rejected" to the `status` field options: `"Pending Approval\nCompleted\nFailed\nCancelled\nRejected"`
   - Add a new field `payment_proof` of type `Attach Image` after `amount_paid` in field_order. Label: "Payment Proof". Not required.
   - Update `field_order` array to include `payment_proof`
   - Update `modified` timestamp to current time

2. Create `memora_admin/api/purchase.py` with a `@frappe.whitelist(allow_guest=False)` function `create_purchase_request`:
   - Parameters: `user_id: str, product_grant_id: str, payment_method: str, payment_proof_url: str | None = None, plan_id: str | None = None`
   - Validate product grant exists, `is_published == 1`, and plan matches player's plan (if plan_id provided). Return specific errors:
     - Product not found / unpublished: `frappe.throw("Product not found", frappe.DoesNotExistError)`
     - Wrong plan: `frappe.throw("Product not available for your plan", frappe.ValidationError)`
   - Look up player profile: `frappe.get_value("Memora Player Profile", {"user": user_id}, "name")`. Throw DoesNotExistError if not found.
   - Check for existing pending transaction: `frappe.db.exists("Memora Subscription Transaction", {"player": player_id, "related_grant": product_grant_id, "status": "Pending Approval"})`. If exists, `frappe.throw("Purchase request already pending for this product", frappe.DuplicateEntryError)`.
   - Get price: `frappe.get_value("Item Price", {"item_code": grant.item_code, "price_list": "Standard Selling"}, "price_list_rate")`. Default to 0.0 if not found.
   - Create the transaction doc with: player, payment_method="Manual-Admin", status="Pending Approval", related_grant, amount_paid, payment_proof (if provided). Use `insert(ignore_permissions=True)`.
   - Return `{"name": trx.name, "status": "Pending Approval"}`
   - Follow the exact pattern in `memora_admin/api/products.py` for structure and imports.

3. Run `bench migrate` to apply the DocType schema change.
  </action>
  <verify>
    - `bench migrate` completes without errors
    - `bench console` can import and call `from memora_admin.api.purchase import create_purchase_request`
    - The DocType JSON has `payment_proof` field and `Rejected` in status options
  </verify>
  <done>

    - Frappe whitelisted API validates inputs, checks duplicates, creates transaction, returns name+status
  </done>

  <action>
1. Create `memora_admin/events/purchase_sync.py` with function `on_purchase_request_created(doc, method)`:
   - Early return if `doc.status != "Pending Approval"` (safety check)
   - Get player display name: `frappe.get_value("Memora Player Profile", doc.player, "display_name") or doc.player`
   - Get product name: load the Product Grant via `doc.related_grant`, then get item name via `frappe.get_value("Item", grant.item_code, "item_name") or grant.item_code`
   - Build Frappe Desk link: `f"{frappe.utils.get_url()}/app/memora-subscription-transaction/{doc.name}"`
   - Send desk realtime alert: `frappe.publish_realtime(event="eval_js", message=f'frappe.show_alert("New purchase request from {player_name}")', user="Administrator")`
   - Query System Manager users: `frappe.get_all("Has Role", filters={"role": "System Manager", "parenttype": "User"}, fields=["parent"])`. Filter to enabled users with email. Follow the exact pattern from `task_utils.py` lines 219-227.
   - Send email via `frappe.sendmail(recipients=recipients, subject=f"New Purchase Request: {item_name} - {player_name}", message=HTML_BODY, now=True)`. HTML body includes: player name, product name, amount_paid, payment method, and a clickable link to the transaction in Frappe Desk.
