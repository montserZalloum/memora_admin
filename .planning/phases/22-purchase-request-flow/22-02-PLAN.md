1. Create `fastapi_app/models/purchase.py`:
   ```python
   class PurchaseRequest(BaseModel):
       product_grant_id: str = Field(..., description="Product Grant ID e.g. GRNT-00239")
       payment_method: str = Field(default="Manual-Admin", description="Payment method")
       payment_proof_url: str | None = Field(None, description="URL of uploaded payment proof image")

   class PurchaseResponse(BaseModel):
       message: str = Field(default="Purchase request submitted successfully")
   ```

2. Create `fastapi_app/services/purchase.py` with class `PurchaseService`:
   - Constructor takes `redis_client: redis.Redis` and `frappe_client: FrappeClient`
   - Class constant: `PENDING_KEY_PREFIX = "memora:pending:"`
   - Method `async def submit_purchase(self, user_id: str, plan_id: str, req: PurchaseRequest) -> PurchaseResponse`:
     a. **Fast duplicate check (Redis)**: `sismember(f"{self.PENDING_KEY_PREFIX}{user_id}", req.product_grant_id)`. If True, raise `HTTPException(status_code=409, detail="Purchase request already pending for this product")`.
     b. **Call Frappe API**: `await self.frappe.call("memora_admin.api.purchase.create_purchase_request", {"user_id": user_id, "product_grant_id": req.product_grant_id, "payment_method": req.payment_method, "payment_proof_url": req.payment_proof_url, "plan_id": plan_id})`. Wrap in try/except for FrappeAPIError:
        - Status 417 (DuplicateEntryError): re-raise as HTTP 409 "Purchase request already pending for this product"
        - Status 404 (DoesNotExistError): re-raise as HTTP 404 with Frappe's message
        - Status 417 (ValidationError): re-raise as HTTP 400 with Frappe's message
        - Other errors: re-raise as HTTP 502 "Failed to process purchase request"
     c. **Write to Redis pending set**: `await self.redis.sadd(f"{self.PENDING_KEY_PREFIX}{user_id}", req.product_grant_id)`. This is AFTER Frappe succeeds (per RESEARCH.md pitfall 2: write Frappe first, Redis second).
     d. Return `PurchaseResponse()`

   Import `HTTPException` from fastapi, `FrappeAPIError` from `fastapi_app.services.frappe_client`. Use structlog for logging. Follow the CatalogService pattern for class structure.

   IMPORTANT: The Redis pending key uses `user_id` (JWT `sub` claim), NOT the Player Profile docname. This must match what CatalogService reads at line 105: `pipe.smembers(f"{self.prefix}pending:{player_id}")` where `player_id` is `user.sub`.
