1. `calculate_commission(face_value: str, quantity: int, commission_type: str | None, commission_value: str | None) -> dict` -- Returns dict with keys: `per_card_commission`, `total_commission`, `net_per_card`, `net_total` -- ALL as `decimal.Decimal` objects. Use `Decimal(str(...))` for all inputs. Use `TWO_PLACES = Decimal("0.01")` and `ROUND_HALF_UP` for quantization at every step. Handle three cases:
   - No commission (type/value is None or empty string): commission=0, net=face_value
   - Percentage: `per_card_commission = (face_value * rate / 100).quantize(TWO_PLACES, ROUND_HALF_UP)`
   - Fixed Amount: `per_card_commission = value.quantize(TWO_PLACES, ROUND_HALF_UP)`
   - NEVER use `frappe.utils.flt()` -- only `decimal.Decimal` per decision [33-01]

2. `resolve_commission(batch_name: str, library: str) -> tuple[str | None, str | None]` -- Returns `(commission_type, commission_value)` following the priority chain (FIN-03):
   - First: Check `Memora Voucher Batch Grant` child rows for `batch_name` where `commission_type` is set. Use `frappe.get_all("Memora Voucher Batch Grant", filters={"parent": batch_name, "commission_type": ["is", "set"]}, fields=["commission_type", "commission_value"], limit=1)`. If found and `commission_type` is truthy, return it.
   - Second: Check library (Customer) custom fields. Use `frappe.db.get_value("Customer", library, ["voucher_commission_type", "voucher_commission_value"], as_dict=True)`. If `voucher_commission_type` is truthy, return it.
   - Third: Return `(None, None)` for zero commission.

Create `memora_admin/memora_admin/services/voucher/invoice.py` with functions:

1. `create_voucher_invoice(customer: str, items: list[dict], remarks: str = "", posting_date: str | None = None) -> str` -- Creates and submits a Sales Invoice via ERPNext ORM. Steps:
   - `si = frappe.new_doc("Sales Invoice")`
   - Set `si.customer = customer`, `si.posting_date = posting_date or nowdate()`
   - Set `si.remarks = remarks`
   - For each item dict (keys: `description`, `qty`, `rate`), append to `si.items` with `item_code="MEMORA-VOUCHER-CARD"`, description, qty, and `rate=float(item["rate"])` (ERPNext expects float for Currency fields -- convert from Decimal ONLY at this point)
   - `si.insert(ignore_permissions=True)` then `si.submit()`
   - Return `si.name`

2. `create_credit_note(customer: str, return_against: str, items: list[dict], remarks: str = "", posting_date: str | None = None) -> str` -- Creates and submits a Credit Note (return Sales Invoice). Steps:
   - `si = frappe.new_doc("Sales Invoice")`
   - Set `si.customer`, `si.posting_date`, `si.remarks`
   - Set `si.is_return = 1`, `si.return_against = return_against`
   - For each item dict, append with NEGATIVE qty: `qty=-abs(item["qty"])`, same `rate=float(item["rate"])`
   - `si.insert(ignore_permissions=True)` then `si.submit()`
   - Return `si.name`
   - If `return_against` is None or empty, raise `frappe.ValidationError("Credit Note requires return_against reference to original invoice")`

3. `create_prepaid_allocation_invoice(allocation_name: str) -> str` -- Orchestrates prepaid invoice creation for a completed allocation. Steps:
   - Load allocation doc: `frappe.get_doc("Memora Voucher Allocation", allocation_name)`
   - Load batch doc: `frappe.get_doc("Memora Voucher Batch", allocation.batch)`
   - Count cards: `card_count = len(allocation.allocation_cards)`
   - Resolve commission: call `resolve_commission(allocation.batch, allocation.customer)` from commission module
   - Calculate amounts: call `calculate_commission(str(batch.face_value), card_count, commission_type, commission_value)`
   - Create invoice via `create_voucher_invoice()` with `description=f"Memora Voucher Cards - Batch {batch.batch_name}"`, `qty=card_count`, `rate=result["net_per_card"]`, remarks including allocation name, batch name, card count, and face value
   - Link invoice to allocation: `frappe.db.set_value("Memora Voucher Allocation", allocation_name, "sales_invoice", si_name)`
   - Link invoice to each card via bulk SQL UPDATE: get card names from `allocation.allocation_cards`, update `sales_invoice` field on all cards in one query
   - Return invoice name

4. `create_prepaid_return_credit_note(allocation_name: str) -> str | None` -- Orchestrates credit note for prepaid returns. Steps:
   - Load allocation doc and batch doc
   - Get card names from allocation_cards
   - Find original invoices: query Voucher Card for distinct `sales_invoice` values on the returned cards
   - Group cards by original invoice. For each group, create a credit note via `create_credit_note()` with `return_against` set to the original invoice name
   - Link credit note to allocation: set `sales_invoice` on the allocation to the last credit note name (or first if single)
   - If cards have no original invoice (defensive), log a warning and skip credit note creation
   - Return the credit note name(s) -- return the single name if one, or comma-separated if multiple

Import `resolve_commission` and `calculate_commission` from `.commission`. Import `frappe` and `frappe.utils.nowdate`.
