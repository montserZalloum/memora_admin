<objective>
Enrich the hierarchy API and settings API to return per-lesson `base_xp` and `max_hearts` values with proper fallback to Memora Settings defaults, update FastAPI models to carry these fields, and formalize the `fsrs` dependency.

Purpose: The hot path rewrite (Plan 03) and hearts bonus XP calculation (Plan 02) both depend on `max_hearts` being available in the hierarchy data and `xp_per_heart` being in the settings. Currently the hierarchy hardcodes `10` for XP when `base_xp` is 0, and `max_hearts` is not returned at all.

Output: Enriched hierarchy JSON with per-lesson `base_xp`/`max_hearts` (with fallback), enriched settings with hearts/FSRS fields, updated Pydantic models, formalized `fsrs` dependency.
</objective>

**hierarchy.py changes:**

1. At the top of `get_subject_hierarchy()`, load Memora Settings defaults for fallback:
   ```python
   settings = frappe.get_single("Memora Settings")
   default_base_xp = settings.base_lesson_xp or 100
   default_max_hearts = settings.default_max_hearts or 5
   ```

2. In the lesson query (line ~111), add `max_hearts` to the `fields` list:
   ```python
   fields=["name", "base_xp", "max_hearts"],
   ```

3. In the lesson_info dict construction (line ~119-123), replace the hardcoded fallback:
   ```python
   lesson_info = {
       "lesson_id": lesson.name,
       "bit_index": bit_index,
       "xp": lesson.base_xp if lesson.base_xp else default_base_xp,
       "max_hearts": lesson.max_hearts if lesson.max_hearts else default_max_hearts,
   }
   ```
   This removes the hardcoded `10` and uses Memora Settings defaults instead.

**settings.py changes:**

Add `default_max_hearts`, `xp_per_heart`, `fsrs_weights`, and `request_retention_days` to the returned dict:
